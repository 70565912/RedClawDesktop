# Remote workspace v0.1.3

Status: approved implementation contract; implementation in progress, not released. See X00-T16 in [MODULE_KANBAN](../runtime/MODULE_KANBAN.md) for current completion and remaining work.

The v0.1.2 capture/recovery qualification and release remain the prerequisite delivery. This feature set ships separately as v0.1.3. Task status belongs in [MODULE_KANBAN](../runtime/MODULE_KANBAN.md).

## Product contract

- A valid desktop connection authorizes this connection's file, clipboard and terminal operations. Do not add a second approval, permission checkbox or per-command confirmation. A future connection password is outside this change. Execute under the Host's ordinary current-user permissions without automatic elevation.
- Keep the Controller's system cursor unchanged. Keep the right Agent sidebar separate from the desktop and terminal.
- File transfer supports both directions, multiple files and recursive folders, including empty folders. The remote browser exposes current-user-accessible directories, not only Agent projects.
- Intercept Ctrl+V only when the remote desktop canvas owns keyboard forwarding. Send the current local clipboard snapshot on demand: Unicode text, HTML/RTF, images and actual file/folder lists. Do not continuously synchronize clipboards. Copy semantics never delete the source.
- The terminal is a complete interactive session beneath the desktop, with expandable/collapsible height. It shares the remote desktop session lifecycle; collapsing does not stop its processes and there is no separate terminal-close control.

## Transfer transaction and operation gate

- Use one active transfer batch per connection for file transfer or clipboard transfer. Before transmitting, settle destination and same-name behavior: keep both (default), overwrite or skip.
- Stream files with 64-bit offsets into owned temporary files, verify length and SHA256, then commit each completed file. Partial transfer must not overwrite a previously complete destination. Cancel removes only this operation's incomplete temporary data; completed files remain in the result list.
- Show scanning, current file, direction, completed/total bytes and files, progress and speed. Report receiving and validation separately from submission to the transport.
- During preparation and transfer, reject remote keyboard/mouse input, capture-region changes, terminal input and new/steered Agent work or approval decisions. Enforce the same gate at both endpoints. Keep video, existing program output and Agent messages flowing. Local reading/layout, cancel and disconnect remain available; already-running programs are not suspended.
- Release pressed input when entering the gate. Clear the transfer reason on completion/cancel/failure without clearing independent capture, consent, lifecycle or geometry reasons. Never replay input accumulated during the transfer.
- Cancel and disconnect invalidate the operation's pending paste and late messages. A disconnected batch ends; the user explicitly starts another attempt after reconnection.
- For clipboard paste, withhold the original Ctrl+V until data arrives. Recheck the original focus target, ordinary desktop, session and input eligibility, publish the clipboard and inject one paste. Focus changes or revoked eligibility cancel the pending paste. A delivered key is not proof of application consumption.
- Successful clipboard files remain in a receiver batch directory with open/cleanup actions; do not delete them when merely sending the paste key. Unsupported clipboard formats get an explicit result.

## Terminal and layout

- Host: Windows ConPTY with a persistent Windows PowerShell session. Support native programs/scripts, Unicode/IME, terminal controls, Ctrl+C, history, completion and dimensions. Own and clean up the shell's process tree.
- Controller: an embedded WebView2 surface and bundled xterm.js, with no remote page/resources or general native scripting bridge. Package a fixed WebView2 runtime and its notices; do not require an unrelated Qt upgrade or runtime CDN.
- Terminal text paste uses terminal input and never changes the Host system clipboard. It obeys the transfer gate.
- A transient reconnect within the same desktop session preserves the terminal process and suspends input. Ending the desktop session, closing the remote window or Host exit ends the terminal tree. A new session does not replay old commands.
- Bound terminal output, backpressure and scrollback; never discard live terminal-control bytes in the middle of a stream to hide backlog. Make scrollback eviction visible.
- Replace the navigation overlay with a height-animated layout item above Agent. Preserve usable Agent composer space at small window sizes. Remember navigation height and terminal visibility locally.
- For new messages and streaming deltas in the selected Agent conversation, scroll both the outer conversation and the newest message's inner text view to the final laid-out tail. Without new content, preserve manual history browsing. Other tasks do not steal selection.

## Host self-restart and update

- Provide fixed maintenance actions for restart and update/restart callable from the connected UI or terminal, using the existing independent full-directory upgrade mechanism. Ordinary shell commands do not implicitly acquire independent ownership.
- Before stopping Host, the independent current-user worker must validate and take ownership of the operation, retained launch settings and recovery data. An update additionally stages/verifies the complete candidate bundle. A failed handoff leaves Host running.
- The Controller keeps the remote window open in a maintenance/reconnecting state. The old terminal and initiating Agent may exit; the maintenance worker continues outside their process jobs and outside any replaced directory.
- Preserve the existing connection identity, role and network settings. Confirm startup separately from restored real media. A reconnect creates a new terminal and never repeats the initiating command.
- Restore the previous complete runtime after an update startup failure. A networking failure alone must not cause repeated rollback. An explicit user close suppresses automatic reopening but does not cancel maintenance already handed off.
- Persist a versioned, owner-local operation receipt. Repeated requests are idempotent; incomplete operations are observable after restart. Raw process identity and launch arguments remain local.

## Interfaces, validation and delivery

The published terminal loads fixed `Restart-RedClawHost` and `Get-RedClawMaintenance` commands. `Restart-RedClawHost -CandidateDirectory <complete runtime folder>` requests an update; omitting the candidate requests a restart. Ordinary programs launched in the shell remain in its Job. The fixed launcher validates the GUI/runtime PID, creation time, executable, interactive user/session and complete bundle before creating a limited current-user scheduled worker. It copies the worker outside the replaceable directory, verifies its exact arguments, and acknowledges the immutable plan hash before any stop. A versioned private active-operation pointer and receipts remain readable after restarting through the saved context. GUI/runtime arguments stay local; a new context refers to the previous operation so another maintenance request cannot overlap its startup check. The portable plan coexists with the supported version-1 repository upgrade plan.

Windows PowerShell starts with a copied child environment that omits the inherited `PSModulePath`, letting the shell build its own module paths. This avoids the [documented intermediate-process PowerShell 7 module-autoload problem](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_psmodulepath#starting-windows-powershell-from-powershell-7). Other variables, including the private maintenance context, remain inherited; the Host process environment is unchanged.

The independent worker waits for a visible GUI and its owned runtime within a 60-second cold-start deadline, separate from media heartbeat limits. Recovery failures still produce a final receipt. An unfinished receipt with no surviving worker is observed as `interrupted` without changing its original evidence or replaying a command. Operation lookup follows the protected immutable launch history, rejecting cycles or a different executable. Repeating an operation ID after subsequent restarts returns its original receipt; a conflicting action or candidate is rejected. Both repository and portable launchers share the same worker identity/argument verification and cancel only their own unacknowledged task on handoff failure. See the [upgrade runbook](../testing/runtime-directory-upgrade.md).

Introduce bounded typed transfer, clipboard transaction, terminal session and remote-operation-gate components rather than expanding the runtime/GUI entrypoints. Add optional versioned capabilities to existing negotiation. Use separate reliable ordered optional data channels for bulk transfers and terminal traffic; priority cancellation/state messages must not queue behind file data. Bind messages to the session epoch and operation ID; reject stale/repeated commits.

The terminal's Control capability is `terminal_version=1`; an absent capability leaves the optional channel disabled. Terminal envelopes use the existing versioned compressed-Protobuf framing, a Host epoch and terminal identity. A changed transport epoch can retain the same shell, but changes its input generation. A new shell resets the display after a surface acknowledgment. The Controller retains at most one unacknowledged 16 KiB input chunk, a bounded 64 KiB pending input queue, and one output chunk awaiting xterm parsing. Lost eligibility clears pending user input; output acknowledgments follow parsing, not receipt. Terminal Open carries a Controller desktop identity retained through transport reconnects. A new desktop identity replaces the prior shell and output. Explicit GUI shutdown sends End and waits asynchronously for Ended before stopping the runtime; the Host acknowledges only after ending its shell tree. End also covers a close before Ready arrives and is independent of the transfer-input gate. A bounded unacknowledged-close diagnostic distinguishes failed delivery from confirmed peer cleanup. Host output has bounded backpressure and persists over a same-session reconnect. Ordinary Controller reconnect retains the Shell and client identity; explicit desktop End still closes them. Reopening the local GUI pipe retries only the bounded unacknowledged output chunk, which the Controller deduplicates before acknowledging. Delayed runtime-stop callbacks are bound to the stopped PID so they cannot terminate its replacement.

Agent IPC already owns typed Agent-envelope parsing, durable conversation delivery and larger bounded queues. The terminal's local pipe permits one pending write with GUI event-driven completion and runtime scheduler polling, without another worker or a journal backlog. Both endpoints verify the owner process identity. File selection, browsing, operation receipts and sampled progress reuse the existing typed GUI/runtime Control stream; terminal display stays on its owner-checked pipe. Keep bulk file bytes in runtime workers, without a second file-data queue in the GUI.

File transfer advertises `file_transfer_version=1` and uses an optional reliable ordered `redclaw-transfer-v1` channel. Absent capability disables this feature. The optional versioned workspace record in Control v1 shares the existing message ID, epoch and replay guard. Prepare/Prepared establishes the Host-owned operation before source selection; each selected root is acknowledged after its incremental scan. Offer/Ready settles totals and receiver readiness before bulk bytes. Cancel bypasses bulk traffic. Both local cleanup, peer completion and a sent completion receipt are required to clear the transfer gate; a disconnected operation still waits for local cleanup and is never replayed. Local-only availability reports carry the operation revision, so a complete operation between two owner ticks still invalidates old input. Agent submission/steering/approval, desktop input and terminal input read the same transfer reason while retaining their independent consent, capture and lifecycle gates. Already accepted Agent output continues, and previously queued work waits until the transfer ends.

Bulk envelopes retain the existing compressed-Protobuf frame limit, with at most 48 KiB file data per frame and 64-bit file offsets. The sender retains one unsent chunk and at most 1 MiB of unacknowledged file data, yields after bounded work and waits for receiving receipts before committing. Entry receipts distinguish receiving, skipping and committed files; receipt of transport data is not a committed-file result. A receiver batch binds to its exact desktop epoch and operation identity, consumes ordered sequences and never replays a commit. Priority cancellation is outside the bulk channel and invalidates queued disk commands; a commit already in progress may finish, and that completed file remains. End the input gate after the worker acknowledges cleanup. Source scanning spools versioned owner-local metadata into an exclusive delete-on-close file instead of retaining the whole file tree in memory. Absolute source paths remain local; only relative destination paths enter bulk messages.

Completed/skipped entry results are written by the disk worker to a versioned owner-local journal, including the actual renamed destination. Cancellation retains that journal and completed files. A finished local Control record exposes its path only to the GUI; the peer boundary rejects this field. The result dialog reads at most 128 records per disk job and uses byte cursors for previous/next pages, without retaining a directory-sized index or blocking the GUI on disk reads. An incomplete record is reported while earlier complete rows remain readable.

Clipboard transfer negotiates optional `clipboard_version` independently of file transfer. Version 1 supports paste; version 2 adds received-file batch listing and fixed folder-open/cleanup actions. A newer endpoint uses the common capability, retaining paste with a version-1 peer. Its typed purpose reuses Prepare/Prepared and the existing bulk worker; the local clipboard sequence is accepted only from the Controller's own GUI and is never sent to the peer. Snapshot format bytes and file manifests are prepared on the disk worker. A fresh Host-owned batch directory receives and verifies the data, then the worker prepares the native clipboard objects while the operation remains blocked. Byte completion is distinct from the Host's final paste receipt.

Received-copy operations identify a batch with 32 lowercase hexadecimal characters; they never accept a peer-specified deletion path. A fixed local container, ownership marker and pinned ordinary-directory ancestors restrict opening/cleanup to the owned batch. Cleanup unlinks reparse entries without traversing their targets, stops future work on cancellation and retains the ownership marker until final removal for safe retry. Listing exposes opaque IDs and creation time. The UI opens only the verified files directory on the Host, and deletion runs on the existing worker with sampled counts. Both operations retain the shared mutation gate until completion receipts; text-only staging with no copied-file entries is removed when the operation ends. Clipboard bulk entries are restricted to payload metadata and file roots, excluding the ownership marker.

The clipboard-specific paste guard binds a pending paste to the original Host window/process identity, focus-event generation, session and independent input-eligibility revision. It consumes the request before publication/input submission, preventing automatic retry after an uncertain OS result. Its native focus tracker uses out-of-context [WinEvent notifications](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook) and [GUI thread information](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo) on the runtime owner thread. That owner processes capture/geometry/input stops before attempting publication and a fixed logical Ctrl+V batch. Empty input-state synchronization releases held Controller keys without revoking the existing control grant. Original V down/repeats/up remain withheld, and another local focus or suspension reason cancels the pending operation.

Native round-trip tests use an exclusive window station to protect the interactive clipboard. The current account cannot create this fixture: [CreateWindowStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createwindowstationw) requires administrator membership when specifying a station name. A follow-up probe using a system-generated station name with CREATE_ONLY returned ERROR_ALREADY_EXISTS; the fixture did not join that existing station. These cases remain explicit environment skips, including the run outside the sandbox. Passing wire/worker/input-callback tests does not establish actual application-paste acceptance.
