# RedClawDesktop v0.1.4

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release is current `main` after v0.1.3. It adds mandatory connection authentication and the connection-page, playback-window, and input-mapping corrections below. There is no signed installer.

## Changes since v0.1.3

- Connection passwords are mandatory on every desktop and workspace channel. The Host stores a verifier and the Client supplies the Host password. A correct password connects automatically and can be remembered by machine code with current-user DPAPI. Wrong passwords end the attempt. Five consecutive failures keep a 30-second cooldown, and each attempt has a 30-second deadline. Passwords keep case and whitespace. There is no passwordless fallback.
- The connection homepage uses two columns, one password field with Show/Hide, and a collapsed More settings panel for permissions, Agent, and network options.
- The playback window titled `RedClaw` is a separate top-level window. It is not owned by `RedClaw Desktop`, so the two windows can be activated independently. Minimizing one does not hide the other. Closing the playback window returns to the main window and does not quit the process.
- Host mouse injection uses the capture desktop's physical pixels. Each `SendInput` batch temporarily uses per-monitor DPI awareness v2 so virtual-screen coordinates match DXGI/WGC capture, then restores the previous thread context. Controller coordinates stay normalized. The wire protocol is unchanged; the Host must be this release or a later build that includes the correction.
- Current Cursor and Codex providers run submitted Agent tasks without an extra task or command approval after the Host has authorized the project. Older peers can still use the existing approval messages.
- Debug builds enable the current-user workspace control pipe by default. Release builds still require `--enable-workspace-control`.
- Capture selection stays normalized until a real frame supplies dimensions. Controller input drains queued keys before publishing the pressed-key snapshot, so a modifier release cannot overtake a chord already in the queue.
- Media sending keeps feedback across ordinary capture-region changes, requests NVENC recovery frames as IDR, and no longer treats one low delivery sample or an unconfirmed probe as a new rate baseline.

## Compatibility and security

v0.1.3 and every older passwordless release are rejected. Both sides must use a build that implements authentication v1. That rejection is a security gate, not a requirement that both programs be the same commit or the same binary. Newer optional fields remain ignorable among builds that share this authentication capability.

Agent work stays inside Host-registered projects. File browsing and the terminal use the Host's current-user permissions and do not elevate. Input, capture, lifecycle, and secure-desktop checks still fail closed.

## Download and upgrade

Download `RedClawDesktop-windows-x64-v0.1.4.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.4). Check the ZIP hash, extract into a new directory, and start `redclaw_desktop.exe`:

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.4.zip -Algorithm SHA256
```

Keep the complete bundle together, including Qt plugins, the protocol codec, the terminal runtime, maintenance scripts, and notices. Do not replace only the EXE. The ZIP contains no credentials, local configuration, runtime logs, or service/debug-bridge executable. An existing source-built Debug directory is a separate artifact.

On the controlled PC, enter the local connection password and click Save, then choose Host and wait. On the controlling PC, choose Controller and enter the Host machine code and that same password. The package is portable and unsigned; Windows SmartScreen may warn. No signed service MSI, pre-login/UAC desktop, or automatic elevation is included.

## Validation boundary

The release publisher builds Release, then checks the finished ZIP hash, required extracted files, and command startup before creating the tag or uploading assets. GitHub then checks the published ZIP on a fresh Windows runner. Focused evidence already recorded for authentication, the connection page, playback-window lifecycle, workspace control, and the adaptive sender is reused. This publication does not repeat the full CTest matrix, a physical cross-LAN run, or physical cursor tracking on a remote Host. The cancelled 2026-09-20 Release sweep and its DHT TCP bind 10013 failures remain a recorded limitation, not a passing full-suite result.

Physical keys, actual application paste, UAC or account interaction, special hardware or topology, and visual judgment stay optional developer evaluations. Local endpoint evidence does not prove every WAN, NAT, or TURN combination. This release makes no general performance-improvement claim.
