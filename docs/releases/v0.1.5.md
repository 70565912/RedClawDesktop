# RedClawDesktop v0.1.5

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release is current `main` after v0.1.4. It adds optional remote system audio and the Controller playback corrections below. Connection passwords, the independent playback window, and physical-pixel Host injection stay as in v0.1.4. There is no signed installer.

## Changes since v0.1.4

- Remote system audio is optional. The Controller button starts Host shared-mode WASAPI loopback, Opus frames travel on the unordered `redclaw-audio-v1` data channel, and the Controller plays them with XAudio2. Peers that do not advertise audio capability still connect; the sound control stays disabled.
- The playback thread initializes a multithreaded COM apartment before creating the XAudio2 mastering voice. Without that initialization the voice fails with `CO_E_NOTINITIALIZED` after a successful decode, so remote sound is silent.
- Playback keeps a fixed lock-free slot ring. When the ring has frames, the thread submits them immediately. When it is empty, the thread sleeps until the next data event. It does not poll on a timer.
- While remote sound stays on, a quiet gap does not close the output. The device is released only when remote sound is turned off or the remote session ends. A source voice that has run out of buffers is started again with the next frame.
- Host loopback emits one captured 20 ms frame per 20 ms. A WASAPI backlog is not drained faster than realtime. A Host still running an older binary keeps its previous capture loop until that Host is upgraded.
- Silent PCM is not sent. A full jitter queue skips ahead. A full slot ring drops the new block.

## Compatibility and security

v0.1.3 and every older passwordless release are still rejected. Both sides must implement authentication v1. Identical commits or binaries are not required. Audio is an incremental capability: a v0.1.4 peer connects, and sound is available only when both sides implement audio v1.

Agent work stays inside Host-registered projects. File browsing and the terminal use the Host's current-user permissions and do not elevate. Input, capture, lifecycle, and secure-desktop checks still fail closed. Secure desktop turns remote sound off with the rest of the ordinary-desktop session.

WASAPI exclusive mode and ASIO bypass the shared audio engine and are not captured.

## Download and upgrade

Download `RedClawDesktop-windows-x64-v0.1.5.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.5). Check the ZIP hash, extract into a new directory, and start `redclaw_desktop.exe`:

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.5.zip -Algorithm SHA256
```

Keep the complete bundle together, including Qt plugins, the protocol codec, the terminal runtime, maintenance scripts, and notices. Do not replace only the EXE. The ZIP contains no credentials, local configuration, runtime logs, or service/debug-bridge executable. An existing source-built Debug directory is a separate artifact.

On the controlled PC, enter the local connection password and click Save, then choose Host and wait. On the controlling PC, choose Controller and enter the Host machine code and that same password. After the desktop is visible, turn on remote sound from the Controller. The package is portable and unsigned; Windows SmartScreen may warn. No signed service MSI, pre-login/UAC desktop, or automatic elevation is included.

## Validation boundary

The release publisher builds Release, then checks the finished ZIP hash, required extracted files, and command startup before creating the tag or uploading assets. The operator verified Controller playback of Host system audio on a Debug build: remote music was audible, and the output stayed open across quiet gaps. That listen check used the existing peer Host, which was not replaced, so it does not prove the 20 ms Host pacing in this package. Focused jitter tests passed 5 cases. This publication does not repeat the full CTest matrix, a physical cross-LAN requalification, or physical cursor tracking on a remote Host.

Physical keys, actual application paste, UAC or account interaction, special hardware or topology, and visual judgment stay optional developer evaluations. Local endpoint evidence does not prove every WAN, NAT, or TURN combination. This release makes no general performance-improvement claim.
