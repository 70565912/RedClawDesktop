# RedClawDesktop v0.1.7

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This maintenance release fixes desktop navigation after Controller restarts and preserves control intent during ordinary desktop/region changes. It also includes the right Shift repair and safer local startup/upgrade handling. The real desktop, connection-password, audio and Agent/workspace baseline from v0.1.6 remains available.

## Changes since v0.1.6

- Controller desktop-navigation requests now advance from the Host's current geometry/media revision. Restarting a Controller against a Host that retains a newer capture region no longer sends an obsolete revision and immediately returns the display selector to the previous desktop. Region acknowledgements for another display still advance the request counter, and a new Host session resets it.
- Ordinary desktop and region changes retain the user's control intent while held input is released. Input resumes only after Host confirmation and presentation of the new geometry. Genuine capture failure, lost authorization, disconnection and expired consent retain their pause/rejection behavior.
- Right Shift uses its normal scan code without the E0 flag on both Controller capture and Host reconciliation. Genuine extended keys such as right Ctrl/Alt retain their extended flag.
- Default Debug launchers automatically build and publish through `build.ps1` when the executable is missing or older than source. They refuse duplicate runtimes before rebuilding; unrelated preparation failures still stop startup.
- Independent upgrade receipts publish complete JSON by atomic replacement with bounded retry, preventing a brief polling-reader lock from aborting handoff.

## Validation and limits

The repaired Debug Controller passes three focused input/UI/capture suites, covering 182 cases with zero failures/skips. A regression first reproduces the obsolete request (expected revision 12, actual 2), then passes with revision synchronization. Eleven isolated startup/build fixtures and the existing startup-rollback/parent-exit fixtures also pass. Detailed evidence and the Release checkpoint are recorded in the [development log](../logs/DEVLOG.md).

The local Controller is independently replaced with rollback retained, automatically reconnects, and continues decoding/presenting real frames without failure increments or synthetic frames. Runtime diagnostics confirm the second display applied with no pending request; the operator verifies desktop selection and normal control. This is Debug deployment/operator evidence, not a Release-package performance measurement. Full CTest, every NAT/TURN combination and long-duration hardware stability are not claimed.

The publication entrypoint checks the final ZIP's SHA256, required/forbidden entries and extracted `--help` startup before uploading. `RELEASE-MANIFEST.txt` identifies the source commit and executable; `SHA256SUMS.txt` identifies the archive. The portable bundle is unsigned and excludes credentials, local configuration, logs and service/debug executables.

## Compatibility and upgrade

No wire schema or authorization downgrade is introduced. Supported authenticated peers use common capabilities without requiring identical commits, program versions or binaries. Passwordless v0.1.3 and older releases remain rejected. Updating the Controller fixes its stale navigation request; the control-intent and right Shift fixes are also included for deployment to either role.

Download `RedClawDesktop-windows-x64-v0.1.7.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.7), verify the archive and extract to a fresh directory. Keep the complete Qt, codec, terminal-runtime, maintenance and notice files together.

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.7.zip -Algorithm SHA256
```

Publication does not replace a currently serving program or change saved credentials. For live replacement, use the independent directory-upgrade and rollback procedure.
