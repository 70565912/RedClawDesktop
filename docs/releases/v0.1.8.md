# RedClawDesktop v0.1.8

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This maintenance release separates desktop-navigation request IDs from Host capture revisions and repairs Controller playback output-resource recovery. It retains the real desktop, connection-password, audio and Agent/workspace baseline from v0.1.7.

## Changes since v0.1.7

- Updated Hosts advertise an optional navigation-command capability. Updated Controllers use a request ID to correlate each selection; the Host assigns the resulting capture revision. A restarted Controller's low request number no longer competes with the Host's retained geometry revision. Unsupported peers continue using the published legacy revision contract.
- Navigation replies must match the pending request and selected display. Input resumes only after the matching acknowledgement and a presented frame of the assigned geometry, in either arrival order. Reconnection renegotiates capabilities and discards previous-session navigation replay. Authorization, focus, consent and capture-failure gates remain enforced.
- D3D11 playback restores its previous render target after a failed buffer resize, rebuilds incomplete output resources and selects the current back buffer only for flip-model swap chains. This addresses a failure mode where decoding continues but the playback output cannot update.
- The isolated rolling-upgrade test retains its existing Host credential when replacing the fixture Host and allows sufficient time for local Debug Control responses.

## Validation and limits

The standard `build.ps1 -Configuration Release` build/publication passes, followed by the complete 125-suite Release CTest collection: zero failures, disabled suites or skipped cases (874.55 seconds). The resulting Release executable also passes five real-capture runtime pairings: new/new and both directions with the actual v0.1.6/v0.1.7 packages. All 17 navigation requests return the expected result, including one unavailable-display rejection followed by recovery.

The preceding Debug repair passed 212 focused cases: protocol, UI, capture recovery, input sessions and real D3D11 integration. Real-capture runtime checks covered a Host at revision 900 accepting request ID 2 and assigning revision 901, repeated region changes, rejection and recovery, and old/new peers in both directions. Actual v0.1.6/v0.1.7 published packages passed both compatibility directions. A local dual-GUI DHT rolling Host replacement passed automatic reconnection and real media presentation.

The v0.1.4/v0.1.5 original packages failed their minimal CLI startup before communication, including with an explicit valid debug-control name; their live mixed-version coverage remains unqualified. Historical incident attribution and all GPU/driver, physical multi-display, NAT/TURN and long-duration combinations are not claimed. Final archive results are recorded in the [development log](../logs/DEVLOG.md).

The publication entrypoint verifies the final ZIP hash, required/forbidden entries and extracted `--help` startup before uploading. `RELEASE-MANIFEST.txt` identifies the source commit and executable; `SHA256SUMS.txt` identifies the archive. The portable bundle is unsigned and excludes credentials, local configuration, logs and service/debug executables.

## Compatibility and upgrade

The added command capability and request ID are optional fields. Supported authenticated peers negotiate common capabilities without requiring identical commits, program versions or binaries. Both updated endpoints are needed for Host-assigned capture revisions; a mixed pair retains legacy semantics. Passwordless v0.1.3 and older releases remain rejected.

Download `RedClawDesktop-windows-x64-v0.1.8.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.8), verify the archive and extract to a fresh directory. Keep the complete Qt, codec, terminal-runtime, maintenance and notice files together.

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.8.zip -Algorithm SHA256
```

Publication does not replace a currently serving program or change saved credentials. For live replacement, use the independent directory-upgrade and rollback procedure.
