# RedClawDesktop v0.1.3

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release combines the previously unpublished v0.1.2 capture/recovery candidate with the remote workspace on current main. There is no separate public v0.1.2 package.

## Changes since v0.1.1

- Capture recovery retains failure stage/category, rebuilds after device/access loss, and uses permission-gated DDA/WGC/GDI fallback. Capture pause releases input; recovery waits for a fresh frame and a new control request. Host cursor composition is consistent across backends; the Controller's system cursor is unchanged.
- Bidirectional file and folder transfer supports empty directories, Unicode paths, keep-both/overwrite/skip policies, SHA256 verification, cancellation and paged per-file results. Only completed files remain after cancellation.
- Clipboard snapshots are sent on demand from remote-canvas Ctrl+V, not continuously synchronized. Text, rich text, images and copied file/folder data use a bounded transaction. Focus/session/input gates protect the final paste; received file batches have owned open/cleanup actions.
- The embedded PowerShell terminal uses ConPTY and bundled WebView2/xterm.js. Collapsing the panel preserves its processes; same-session transport reconnect retains the shell. Explicit desktop close ends its process tree. Terminal paste does not replace the Host system clipboard.
- File/clipboard transfers pause new desktop input, terminal input and Agent mutations while keeping video and existing output alive. Completion never clears unrelated authorization, focus, capture or lifecycle restrictions.
- Independent current-user restart and complete-directory upgrade validate handoff and runtime ownership, preserve launch settings and support startup rollback. The worker survives the initiating Agent or terminal job; repeating an operation does not replay commands.
- Agent updates preserve pending approvals during Provider output, retain durable state on authorization rejection and improve message layout, expansion and conversation following. Controller startup uses the routed IPv4 address on multi-address adapters.
- Local validation selects affected suites, deduplicates them and records machine-readable results. Human-dependent cases are excluded from automation and release acceptance. The publisher validates the final extracted ZIP before creating its release tag or uploading assets.

## Compatibility and security

Supported versions negotiate their common capabilities; identical commits or binaries are not a connection requirement. New file, clipboard, terminal and capture-status fields are optional and versioned. Older peers keep their existing desktop/Agent behavior and do not expose unsupported workspace features.

Agent work remains scoped to Host-registered projects. File browsing and terminal commands are separate connected-desktop capabilities using the Host's current-user permissions, without automatic elevation. Input, capture, lifecycle and secure-desktop safeguards remain fail closed.

## Download and upgrade

Download `RedClawDesktop-windows-x64-v0.1.3.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.3). Check the ZIP hash, extract into a new directory and start `redclaw_desktop.exe`:

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.3.zip -Algorithm SHA256
```

Keep the complete bundle together, including Qt plugins, protocol codec, terminal runtime, maintenance scripts and notices. Do not replace only the EXE. The ZIP contains no credentials, local configuration, runtime logs or service/debug-bridge executable. Existing source-built Debug installations are separate artifacts.

The package is portable and unsigned; Windows SmartScreen may warn. No signed service MSI, pre-login/UAC desktop access or automatic elevation is delivered by this preview. Agent-assisted upgrades use the [independent full-directory procedure](../testing/runtime-directory-upgrade.md).

## Validation boundary

Serial Debug/Release builds succeeded. The unchanged runtime implementation reuses recorded local endpoint, supported-version/reconnect and functional results; the reorganized 24-suite unattended selection passed without case skips. Completed functional tests are not repeated merely to publish. Final archive integrity/extracted startup are checked before upload, and GitHub checks the published ZIP on a fresh Windows runner. Exact run scope and publication status are recorded in [PROJECT_STATE](../runtime/PROJECT_STATE.md) and the [development log](../logs/DEVLOG.md).

A redundant Release CTest sweep was cancelled at the operator's request. It had recorded four DHT listener failures with Windows TCP bind error 10013 before cancellation; it is not a passing full-suite result. This preview retains that diagnostic limitation and does not claim a newly passing 110-suite Release sweep.

Physical keys, actual application paste, UAC/account interaction, special hardware/topology and visual judgments are optional developer evaluations, not pending release requirements. Local dual-endpoint evidence does not establish every WAN/NAT/TURN or hardware combination. Performance observations are hardware- and workload-specific; this release makes no general performance-improvement claim. See the [automated-only test matrix](../testing/test-matrix.md).
