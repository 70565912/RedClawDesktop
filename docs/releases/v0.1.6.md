# RedClawDesktop v0.1.6

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release packages current main after v0.1.5. It includes the accepted desktop-stream optimization work, recovery fixes and reproducible Windows/Linux checks below. Connection passwords, optional system audio and the independent playback window remain available. The portable bundle is unsigned; no service MSI is included.

## Changes since v0.1.5

- **X00-T27:** bounded visible-log batches and no hidden-view refresh; fixed nominal desktop codec timing (30 FPS, time base 1/30, GOP 60); bounded capture-frame pooling; publication before asynchronous thumbnail preparation/JPEG/send; confirmed GPU encoder input with generation-safe CPU fallback; bounded frame traces and stage attribution.
- QSV uses aligned, independently owned NV12 surfaces. DDA frame waits occur outside the shared GPU-device critical section. GPU paths still include copies and do not constitute end-to-end zero-copy.
- **X00-T28:** cancellable Windows deadline waits reduce measured ordinary pacer wake overshoot in the retained local comparison. Condition-variable fallback remains available.
- **X00-T29:** codec bitrate follows geometry/quality rather than the current submission cadence. Starting or resizing at 1/5 FPS no longer creates a permanently low budget when motion resumes.
- **X00-T30:** blocked sender admission refreshes retained packet expiry without inventing receiver ACKs or loss. New controlled tests distinguish expiry refresh from absent-refresh failure.
- Sender diagnostic tests show that wait elapsed includes predicate-mutex reacquisition and separate delayed transport-state/send callbacks into their existing trace buckets. Four explicit uint64_t min/max deductions and two capture platform guards allow the production-code Linux minimal build; Windows policy is unchanged.
- Wrapped-log history eviction preserves the visible block and its layout-line offset, fixing a one-record scroll shift found by the Release checkpoint.
- Host reconnection resets navigation revisions; ICE UDP bind failure offers an actionable port-change prompt. Remote clipboard copies return to the Controller; clipboard-4 change notices and optional Host source revisions are enabled only at the negotiated common capability. User exit and verified directory-upgrade exit handling are retained.

## Validation and limits

The accepted scope and retained measurement provenance are recorded in the [T27 phase report](../testing/video-link-optimization-x00-t27.md), [baseline report](../testing/video-link-baseline-20260928.md), [GPU-input report](../testing/video-gpu-input-p5-20260929.md), and [T29–T31 bounded checks](../testing/video-link-linux-checks-20261001.md).

- Retained Windows and Linux minimal checks each pass three complete groups: nine CTest executions, 21 GoogleTest case executions, 60 software-encoded/decoded frames and zero failures/skips. T30/T31 have a further local six-CTest/18-case pass after LP64 repairs. Fixed synthetic codec input proves the production software encode/decode contract, not physical desktop capture or WAN performance.
- Retained Intel P5 paired real DDA/QSV measurements reduce median preparation 7.482→0.361 ms and total encoding 15.248→8.175 ms, with higher GPU-path private memory. Those results belong to the measured Debug profiler and fixed geometry; they are not a new Release-package performance measurement.
- T27 closes under the operator-approved source-benefit criterion together with the documented scoped P3/P4/P5 measurements. Unmeasured P1 tail and isolated P2 latency percentages are not invented. Linux condition-variable checks do not qualify Windows native timers or GPU hardware.
- T30/T31 are **temporarily closed after bounded investigation**. The historical admission stall and 6.215-second send gap still have unknown causes (`incident_complete=false`). This release does not claim those incidents were fully resolved or that every end-to-end latency target passed.

The standard Release build/publish succeeds. Thirty selected unattended suites have final passing outcomes: the initial 24/27 pass plus focused repair/supplemental results (34 CTest executions overall). The three original failures are retained; two stale congestion fixtures are aligned with current sustained-feedback/demand semantics, and the wrapped-log scrolling defect is fixed. Zero final failures or observed skips; the full 125-suite matrix is not claimed. The portable-package preflight passes SHA256, forbidden/required-entry checks and extracted `--help` startup (exit 0), with 336 files and executable hash12 `c299311c033d`. The publication script repeats those checks for the final tagged ZIP. Archive identity is supplied by `RELEASE-MANIFEST.txt` and the external `SHA256SUMS.txt`. Physical-input, UAC/account, special topology/hardware and visual evaluations remain developer-selected coverage. No new five-minute Intel/end-to-end acceptance is claimed by publication.

## Compatibility and upgrade

Both peers must implement authentication v1; passwordless v0.1.3 and older releases remain rejected. Supported peers use their common capabilities and do not require identical commits, versions or binaries. Clipboard-4 notifications are incremental: common versions 1/2/3 retain their original operations and unsupported new calls fail explicitly. The compiler and timing fixes introduce no authentication downgrade.

Download `RedClawDesktop-windows-x64-v0.1.6.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.6). Verify the ZIP hash and extract into a fresh directory. Keep the full bundle together, including Qt plugins, MSVC runtime, protocol codec, terminal runtime, maintenance scripts and notices. The ZIP excludes local configuration, credentials, logs and debug/service executables.

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.6.zip -Algorithm SHA256
```

Publishing this archive does not upgrade or restart a currently serving Host. Existing session and per-user credentials remain local. For an actual Host replacement, use the documented independent rollback and session-publication procedure.
