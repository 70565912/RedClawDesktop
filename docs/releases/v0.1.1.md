# RedClawDesktop v0.1.1

Release type: Windows x64 Developer Preview / GitHub Pre-release.

## Changes since v0.1.0

- Made Codex CLI discovery reliable when the GUI does not inherit Codex Desktop's temporary PATH. A native CLI on PATH remains preferred, followed by the current user's Codex Desktop CLI and the existing PowerShell launcher fallback.
- Kept Agent login status, bounded command output, selected CLI path, cancellation, failures, and recovery guidance visible inside the settings dialog.
- Compacted long Provider model lists and made the Agent settings content scrollable so the account controls remain reachable.
- Broadened the compatibility retry for Codex configurations that reject an unsupported `service_tier` value.
- Added a GitHub Actions smoke workflow that downloads the final published ZIP, verifies its checksum and required files, then runs the packaged command entry without rebuilding dependencies.
- Documented why GitHub's fresh Windows runners install their own dependencies and which desktop, GPU, UPnP, ICE, input, and Provider checks still require local or physical machines.
- Kept runtime-control write latency as reported telemetry while making the regression gate verify event-loop independence directly, so host scheduling speed no longer turns the functional check into a false failure.

## Install

1. Download `RedClawDesktop-windows-x64-v0.1.1.zip` and `SHA256SUMS.txt`.
2. Compare the archive hash with `SHA256SUMS.txt`.
3. Extract into a new directory and launch `redclaw_desktop.exe`.
4. Use the same release on both Host and Controller.

The package is portable, unsigned, and does not install the Windows service. Windows SmartScreen may display a warning.

## Network setup

The product default is UDP 55000 for ICE. UPnP maps this ICE port when enabled. For manual router configuration, map the configured UDP port externally to the same UDP port on the RedClaw machine. The DHT listening port does not need a manual mapping.

Two different machines may both use 55000. Two RedClaw instances on the same machine need distinct ICE UDP ports; project tests use Host 55000 and Controller 55001.

## Validation scope

- Standard Debug and Release builds on Windows x64.
- Non-E2E unit tests and focused Agent settings and Provider regressions.
- Local portable-package extraction, checksum, command-entry, and GUI startup checks.
- Local dual-GUI real capture, transport, decode, presentation, and three-channel validation.
- GitHub-hosted verification of the exact assets downloaded from the published Pre-release.

The GitHub package check is not evidence of real desktop capture, D3D11 hardware presentation, UPnP, cross-site ICE, physical input, or real Provider login. Hardware-sensitive performance metrics remain observed product metrics and do not block this functional preview by themselves.

## Known limitations

- No signed MSI or unattended service installation is distributed in this release.
- Cross-site behavior still depends on NAT, CGNAT, firewall, ISP, and TURN availability; not every combination has been validated.
- Mobile clients and macOS/Linux desktop support are not included.
- Hardware codec and capture availability depends on the GPU, driver, Windows version, and active desktop session.
- Secure desktop and missing or expired authorization intentionally pause or reject remote input.

## Integrity

`RELEASE-MANIFEST.txt` inside the ZIP records the public Git commit, executable SHA256, archive file list, and build metadata. `SHA256SUMS.txt` published beside the ZIP records the final ZIP SHA256. GitHub `main`, the peeled `v0.1.1` tag, and this Release must refer to the same source commit.
