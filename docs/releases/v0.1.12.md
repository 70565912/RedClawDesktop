# RedClawDesktop v0.1.12

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release repairs Controller-to-Host clipboard paste under capability 5, so shortcut and application-menu paste finish or show a failure instead of stalling, and it includes the Controller workspace updates that landed after v0.1.11.

## Changes since v0.1.11

- Under clipboard capability 5, Host shortcut paste used `paste_verified_clipboard`, which requires an in-flight transfer. Ctrl+V, Shift+Insert, and the Host application's paste menu therefore failed with `clipboard_input_revoked`, and a native `GetData` could wait with no timeout. Shortcut paste now uses `paste_shortcut_clipboard`. It does not require a transfer gate. It stays bound to the same input lease, focus, and ordinary desktop, and it is refused while a transfer gate is held.
- A stopped native clipboard port restarts with a 1 s to 30 s backoff. Busy clipboard capture and install are retried. A stale, busy, or missing-port demand is cancelled with an error. An unanswered text or image paste wait ends at 15 seconds, and a shortcut capture wait ends at 5 seconds. The Controller shows the failure. File-paste flows stay on explicit cancel and keep their previous unbounded wait. The wire protocol is the same.
- The floating Connection panel no longer shows the scrolling runtime log. Pairing, handshake, live link, path and picture status, and reconnect/disconnect stay on the panel. The connection page keeps its own log. Diagnostics stay in capacity-limited files, and each startup deletes `redclaw-*` logs left by processes that have exited.
- The connection page, connection progress, and remote desktop share one window. The Connection overlay shows the staged progress and hides after the first frame. Fullscreen is the toolbar control or `Ctrl+Alt+Enter`. The workspace uses the dark charcoal-blue canvas and aligned toolbar buttons. Desktop navigation is a compact monitor row above the preview. The overlay sizes itself to the available window. Clipboard file progress opens only after the paste is confirmed.
- The Host upgrade publication check reads the status file as UTF-8.
- Root engineering status is `SPEC.md`, `PROGRESS.md`, and `DECISIONS.md`, with the onboarding gate at the top of `AGENTS.md`. Those files do not change runtime behavior.

## Compatibility and upgrade

Native on-demand paste still needs **clipboard capability 5 on both endpoints**. Supported authenticated older releases still connect through the common capability set. The same version, commit, or binary hash is not a connection requirement. A mixed old and new pair still connects. Shortcut paste needs this Host; an older Host keeps the previous shortcut-paste failure, and a new Controller reports that failure when the wait ends. Passwordless v0.1.3 and earlier remain rejected.

For a serving Host, prepare the complete candidate and an independent recovery worker before replacing the running program. The worker keeps the previous directory and restores it if startup or required Host publication fails.

## Validation and limits

PR #5 CI jobs `build-and-test`, `hint`, and `docs-guard` passed. Ryan confirmed bidirectional Controller-to-Host clipboard paste on live two-machine Debug builds of the fix (commit `ce0990fd`, now on main as `c8ec2a2`). The Windows Release portable package and `scripts/release/test-portable-package.ps1` smoke are produced when the publish script runs later.

File-paste flows stay unbounded. The portable package is unsigned. Screenshot proof is outside this note. On a mixed pair, shortcut paste needs the new Host.
