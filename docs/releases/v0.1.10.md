# RedClawDesktop v0.1.10

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This release adds connected-Host protection against ordinary Windows Update restarts and repairs the retained Controller layout when a playback window reconnects.

## Changes since v0.1.9

- A GUI Host started as administrator automatically holds a renewable Windows Update active-hours policy while an authenticated desktop connection is live. No Controller setting is required. Downloads, installation mode and update services remain unchanged.
- Disconnect, runtime stop or GUI exit restores the original restart-policy values. A versioned recovery record supports interrupted-owner recovery at the next elevated GUI startup. Concurrent Hosts cannot restore a live owner's lease; external administrator/policy changes are preserved.
- The connected Host registers a shutdown reason and rejects cancelable shutdown queries. Ordinary manual shutdown can show the same session-in-use reason; disconnect first or explicitly continue through Windows. Logoff and critical/forced shutdown remain available. Non-administrator startup reports the missing permission, and configured forced deadlines are reported as a limitation. This is not an absolute block against every forced Windows restart. See the [protection contract](../architecture/host-update-restart-protection.md).
- A reused playback window settles its pending layout before publishing the viewport, including after its first ready frame. This repairs the compact centered-canvas regression without resending unchanged viewport requests. D3D11 diagnostics include canvas/parent dimensions.
- Include the verified AMD AMF dependency overlay, current FFmpeg pixel-format API compatibility and Windows CI ownership/Unicode fixture repairs already on main after v0.1.9.

## Validation and limits

The implementation passes the standard Debug build, complete candidate publication/startup and 28 focused automatic cases, including 13 new policy/native/status checks. Registry tests use isolated HKCU roots; the native Windows fixture sends only a shutdown query, without actually shutting down. Earlier layout verification includes a failing-before/fixed-after regression, D3D11 integration and three isolated real-capture reconnect rounds.

Release build, automatic CTest and package qualification are recorded in the [development log](../logs/DEVLOG.md). The package checks archive SHA256, required/forbidden contents, embedded source/executable identity and extracted `--help` startup. Published assets include `SHA256SUMS.txt` and an inner `RELEASE-MANIFEST.txt`.

No real Windows Update installation or forced restart is initiated for qualification. Actual managed-policy, Windows Home, old-OS, physical-input, GPU/NAT/TURN and visual combinations not exercised are not claimed. The portable package remains unsigned.

## Compatibility and upgrade

There is no new wire capability or persisted peer-protocol requirement. Supported authenticated releases continue using their common capabilities; matching versions, commits or hashes are not required. Update the Host for restart protection and the Controller for the retained-layout repair. Passwordless v0.1.3 and earlier versions remain rejected.

Download `RedClawDesktop-windows-x64-v0.1.10.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.10), verify the archive and extract the complete directory.

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.10.zip -Algorithm SHA256
```

For a serving Host, use the existing independent upgrade worker with recovery prepared before stopping the old session. Run the new GUI Host as administrator to enable the temporary machine-wide update policy.
