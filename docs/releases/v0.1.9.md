# RedClawDesktop v0.1.9

Release type: Windows x64 Developer Preview / GitHub Pre-release.

This maintenance release restores ordinary-application control when authorized remote mouse movement stops taking effect. It adds a bounded recovery prompt, immediately re-arms detection after observed cursor progress, and improves independently recoverable Host updates.

## Changes since v0.1.8

- The Host observes real authorized absolute mouse movement. After three qualifying stationary-cursor samples, it requests activation of an owned recovery window. It never synthesizes or replays input. Secure-desktop, authorization, lease, capture, transfer and held-input gates remain enforced.
- Observed cursor progress clears the previous attempt's cooldown and retry budget. A later failure can trigger promptly after fresh qualifying samples; recovery attempts with no progress retain the 30-second backoff and three-attempt limit. The prompt stays open while foreground and closes when the user changes windows, closes it, or loses an eligible context.
- The prompt matches RedClaw's dark styling and scales with DPI. It displays “当前激活窗口禁止键盘鼠标消息注入，请关闭此软件窗口。” with the close instruction emphasized. It does not close another application automatically.
- Host maintenance can require fresh session publication from the replacement instance before reporting success. Startup/publication failure retains the independent rollback path. Graceful exit validates the exact local pipe owner without requesting a diagnostic snapshot, and maintenance resume retains already declared Agent projects.
- Developer-selected lifecycle diagnostics and a bounded native input probe provide separate evidence for process exits, injection and actual window consumption.

## Validation and limits

The Debug implementation passed 16 focused recovery regressions, three DPI content previews and operator-assisted testing on the remote Host. Three successful recovery activations were separated by 8.605 and 14.471 seconds, both below the old 30-second cooldown; the operator confirmed ordinary windows were clickable after recurrence. These intervals include operator actions and are not failure-detection latency. Independent Host deployment, complete rollback-manifest validation, fresh publication and real media reconnection were verified.

The Release build and all 126 automatic suites are covered with no unresolved failures or skips. The initial sweep passed 123 suites; three existing test fixtures exposed notification, thread-start and asynchronous-render races. After repairing those fixtures without changing production behavior or the 500 ms media threshold, the adaptive suite and lifecycle thread group each passed 20 repetitions, the complete UI suite passed, and its four affected cases passed three repetitions. Unaffected passing cases were retained from the first sweep. The maintenance scripts passed 16 focused checks and static analysis. Detailed results and final package verification are in the [development log](../logs/DEVLOG.md).

The package entrypoint checks the archive hash, required/forbidden entries and extracted command startup. `RELEASE-MANIFEST.txt` identifies the source commit and executable; `SHA256SUMS.txt` identifies the ZIP.

Detection is a conservative cursor-stall heuristic. It does not identify a third-party filtering mechanism, cover keyboard-only/button-only rejection, or guarantee that a protected application accepts injected input. The remedy changes foreground to the recovery prompt; its purpose is to recover control of ordinary applications. The portable bundle remains unsigned; untested GPU, physical-input, NAT/TURN and long-duration combinations are not claimed.

## Compatibility and upgrade

The input-recovery change adds no wire-protocol requirement. Supported authenticated versions continue negotiating their common capabilities; equal commits or binaries are not required. Only the updated Host is needed for the recovery prompt. Passwordless v0.1.3 and older releases remain rejected.

Download `RedClawDesktop-windows-x64-v0.1.9.zip` and `SHA256SUMS.txt` from the [GitHub prerelease](https://github.com/70565912/RedClawDesktop/releases/tag/v0.1.9), verify the archive and extract to a fresh directory. Keep the complete Qt, codec, terminal-runtime, maintenance and notice files together.

```powershell
Get-FileHash .\RedClawDesktop-windows-x64-v0.1.9.zip -Algorithm SHA256
```

For a serving Host, build and validate the candidate first, then use the independent directory-upgrade worker with rollback before stopping the old session.
